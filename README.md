# 陽だまり家事サポート（架空案件）

愛知県瀬戸市のシニア世帯向け家事代行サービスという設定で作った、**架空のポートフォリオ用サイト**です。
実在の事業者ではありません。会社名・住所・お客様の声・保険の記載はすべて架空のものです。

## 構成

```
index.html      トップ（表紙・ヒーロー・安心3つ・お困りごと）
service.html    サービス内容と料金
flow.html       ご利用の流れ
voice.html      お客様の声
faq.html        よくある質問
reserve.html    ご予約・ご相談（フォーム）
thanks.html     送信完了（noindex）
privacy.html    プライバシーポリシー
tokushoho.html  特定商取引法に基づく表記

build.py        6+3ページを書き出す。ヘッダー・フッター・<head> はここ1か所
src/            各ページの本文だけを置く
assets/         style.css / main.js / 画像
_headers        Netlify・Cloudflare Pages 用のセキュリティヘッダとキャッシュ設定
robots.txt / sitemap.xml
```

### ビルド

```bash
python3 build.py
```

ビルド時に**リンク切れを検査**します。飛び先のないリンクがあると、
そこで止まって場所を教えます。1ページを複数ページに分けたとき、
ページ内リンク（`#reserve` など）が残ってどこにも飛ばなくなる事故が
実際に起きたためです。

ヘッダーやフッターを直すときは `build.py` を、本文を直すときは `src/page-*.html` を編集して
ビルドし直します。**生成された `*.html` を直接編集しても、次のビルドで上書きされます。**

9ページに同じヘッダーをコピーして持つと、1か所直すのに9回同じ作業が要ります。
それを避けるためだけの、依存ライブラリなしの小さなスクリプトです。

## 性能

単一HTMLに画像をbase64で埋め込んでいた版から、外部ファイル + レスポンシブ画像に変更しました。
ローカルHTTPサーバに帯域制限をかけた実測値です。

| 回線 | 変更前 初期描画 | 変更後 初期描画 | 転送量 |
|---|---:|---:|---|
| 光 50Mbps | 384ms | 200ms | 338KB → 110KB |
| 4G 4Mbps | 672ms | 432ms | 同上 |
| 低速 1.6Mbps | 1,764ms | 1,124ms | 同上 |

やったこと:

- **表紙写真を `<picture>` + `srcset` に。** AVIF / WebP / JPEG の3形式 × 800/1200/1600px。
  AVIFは元の249KB（base64）に対し**69KB**。CSS背景ではなく `<img>` にしたのは、
  背景画像はブラウザの先読みが見つけられずLCPとして扱われないためです。
- **Webフォントを7ウェイト → 3ウェイトに。** 本文500・太字700・明朝700だけを読み込みます。
  CSSの `font-weight: 800/900` は700に統一しました。
- **フォントCSSを非同期読み込みに。** 第三者ドメインへの `<link rel=stylesheet>` は描画を止めます。
  届くまでは明朝・ゴシックの代替で表示されます。
- **CSS / JS を外部ファイルに。** 2ページ目以降はHTMLだけの転送で済みます
  （`_headers` で `/assets/*` に1週間のキャッシュを設定）。

## セキュリティ・法務

- `_headers` に CSP / HSTS / X-Content-Type-Options / Referrer-Policy / X-Frame-Options /
  Permissions-Policy を設定しています。**公開先に合わせて `form-action` の送信先ドメインを直してください。**
- フォームには**ハニーポット**（人には見えない入力欄）と**二重送信の防止**を入れています。
- プライバシーポリシーと特定商取引法の表記は**雛形**です。実際の運用に合わせて必ず確認・修正してください。
- 外部ライブラリへの依存はありません。

## 料金カードの開閉

各プランは「時間あたりの料金」までを出し、点線から下（1回あたりの合計と、できること）は
「料金とできること」を押したときだけ開きます。4枚並ぶと縦に長く、比べたい
「時間あたりの料金」が画面に収まらなかったためです。スマホの `service.html` は
5,334px → 4,688px になりました。

**開閉ボタンは `main.js` が作ります。** HTMLには書きません。書いてしまうと、
スクリプトが動かない環境で中身が閉じたまま開かなくなります。いまの作りなら
その場合は最初から開いた状態で残ります。

ただし、比較の要である「1回 6,400円」が既定で見えなくなりました。
下の「料金のかんたん試算」で同じ数字は出せますが、カードだけを見て
比べたい人には一手間増えています。

## 選んだプランを予約フォームへ引き継ぐ

料金表の「このプランで予約する」と、料金試算の「この内容で相談する」を押すと、
`reserve.html?plan=biweek&hours=4` の形でプランと時間を持っていきます。
フォーム側は `<option data-key="...">` を照合して初期値にし、
「反映しました」のお知らせを出します（変更もできます）。

- 対応する `data-key` — プラン: `trial` / `week` / `biweek` / `spot` / `undecided`、
  時間: `2` / `3` / `4` / `5` / `ask`
- 料金表のボタンは固定値、試算のボタンは選択に合わせて `syncCta()` が書き換えます
- 直接 `reserve.html` を開いたときはお知らせを出しません
- 知らない値・値なしのときは何もせず、既定の選択のままにします

一度選んだものをもう一度選ばせない、という以上の意味はありませんが、
入力が1画面で終わるかどうかは離脱率に直接効きます。

`build.py` のリンク切れ検査は、存在の確認をする前に `?...` を落とします。

## フォームを実際に動かすには

`src/page-reserve.html` の `data-endpoint=""` に送信先URL（Formspree、Basin、
Netlify Forms、自前のWorkerなど）を入れてビルドし直すだけです。

- 未設定のときは、画面上で完了表示を出すだけの動作になります
- 設定すると、送信 → `thanks.html` へ移動 という流れになります
- 通信に失敗した場合はエラーを表示し、ボタンを押せる状態に戻します

## アクセシビリティ上の決めごと

利用者の多くが高齢者であることを前提にしています。

- **文字サイズは2段階（標準・大）**。`localStorage` に保存し、ページを移動しても維持します。
  ヘッダーの社名と表紙の文字だけは `px`/`vw` 基準で、この設定に追随させません
  （追随させると狭い画面でヘッダーが崩れます）。
- **エラーは色だけで伝えません。** 枠線の色に加えて、テキスト・アイコン・
  フォーム冒頭のサマリー（`role="alert"`）でも伝えます。
- **エラー行の場所は、一度でも送信を試したあとだけ確保**します（`.is-validated`）。
  表示・非表示で下の要素が動くと入力を直している最中にボタンを押し間違えますが、
  まだ何も起きていないうちから空行を空けるとフォームが間延びするためです。
  この切り替えでフォームの高さは927px→761pxになり、ズレは0pxのままです。
- **タップ領域は44px以上。** 同意チェックボックスは行全体を押せます。
- **本文のコントラストは6.5〜14.7:1**、表紙の白文字は写真の明るい部分でも4.5:1以上。
- 最小の文字サイズは13px（以前11.2pxの箇所がありました。ドロワーの文字サイズ欄にも
  残っていたので、こちらも直しています）。
- **スクリプトは機能ごとに `run()` で囲んで独立させています。** 1本につなげると、
  途中の例外でメニューまで止まります。
- 1000px以下ではナビをドロワーに切り替えます（Escape・背景クリックで閉じ、フォーカストラップあり）。
- **ドロワーの小項目**は `build.py` の `DRAWER_SUB` で定義します。項目名の右にある
  開閉ボタンを押すと、ひとつ下に出ます。いまは「サービス・料金」の下に
  「料金試算」（`service.html#calc`）だけを置いています。枠線・背景・最小高さ48pxは
  上の項目とそろえてあり、字下げはしません（ひとつ下の行に見えるだけ、が意図です）。
- **ドロワーのお電話ボタン**は、丸い受話器バッジ＋見出し「お電話でのご相談」＋番号＋
  受付時間の3行構成にしています。番号だけを置くと、それが押せるものだと気づかれません。
- **ドロワーの文字サイズボタンは44px・文字15.2px**です。ヘッダー版の`.7rem`（11.2px）を
  そのまま使っていたため、いちばんこの機能を必要とする人にいちばん小さいボタンを
  出していました。画面の低い端末では、まわりの余白だけを詰めて44pxは守ります。
- **ご予約の電話カードは、スマホではカード全体が発信リンク**です。番号の行だけだと
  的が24pxですが、カードなら150px以上になります。`a::after{inset:0}`で広げているので、
  読み上げ上のリンクは番号のまま1つです。
- **サブページの見出しは、大きさと太さを本文の見出しと同じまま**、色（藍）と
  下線の飾りだけで目立たせています。濃い背景の節（`.reserve`）では白抜きにします。
  同系色にすると文字が完全に消えるためで、実際に一度そうなりました。
  検証は色の値ではなく、背景とのコントラスト比（全ページ9.6:1以上）で見ています。
- **ドロワーの高さは `100dvh`** です。`100vh` だとスマホのブラウザ下部ツールバーの裏まで
  伸びてしまい、最後の項目（よくある質問・ご予約）が押せなくなります。あわせて
  画面が低いとき（`max-height:760px`）は項目を詰め、文字サイズ「大」でも6項目が収まるようにしています。
- **ページ先頭へ戻るボタンは `focus({preventScroll:true})`** を使います。素の `focus()` は
  スクロールを伴うため、スムーススクロールが中断されて途中で止まります。
- **`ol` には `list-style:none` が要ります。** ご利用の流れは `<ol>` の各項目に番号を
  自分で置いているので、ブラウザ既定のマーカー（`1.`）を消さないと番号が二重に出ます。
  リセットCSSで `ul` だけを消していたために実際に起きました。`ol` 全体ではなく
  `.flow` に限って消しているのは、本文中の箇条書きの番号まで消さないためです。

## 公開前に記入が必要な箇所

- **電話番号は架空の `0561-00-0000`** を入れてあります。`0561` は瀬戸市の市外局番、
  局番の `00` は日本国内で未割当なので、**実在の相手には絶対につながりません**。
  実在しそうな番号を仮に置くと誰かの電話が鳴ってしまうため、この形にしています。
  差し替えは `build.py` の `TEL_DISP` / `TEL_HREF` と、`src/page-index.html`・
  `src/page-reserve.html`・`src/page-thanks.html`・`src/page-tokushoho.html` の直書き箇所。
- **所在地・郵便番号**（フッターと `build.py` の `BUSINESS`）
- **`build.py` の `SITE`** を実ドメインに（canonical / OGP / sitemap に反映されます）
- **JSON-LD の `telephone`** — 番号が決まるまで項目ごと入れていません
- プライバシーポリシー・特定商取引法の表記の中身

## 内容についての注意

**おためしプランが割引になっていません。** 2時間5,500円は時間あたり2,750円で、
定期・週1回と同じ単価です。交通費を含む1回あたりも6,400円で一致します。
初回を割安にする意図があるなら金額の見直しが必要です。

「お客様の声」3件は架空の文章です。損害賠償保険の記載も未検証です。

承っていないサービス（お料理、通院・お出かけの付き添い、エアコンなどの分解洗浄、身体介護）は
料金表の下に明記しています。

## 検証

`python3 -m http.server` で配信し、Playwright で確認しています。

- 全9ページ: ヘッダーが常時表示（sticky）、ナビ5項目、h1が1つ、
  title/description/canonical/og:image、構造化データが壊れていないこと
- ナビ・ドロワーからの遷移、現在地の表示（`aria-current="page"`）
- 料金の整合（4プランとも 単価×2＋交通費900円＝表示中の合計）、料金試算の計算結果
- フォームの検証・エラー表示・完了表示、ハニーポット、送信先の差し替え可否
- プランと時間の引き継ぎ（料金表4ボタン・試算ボタン → フォームの初期値と送信内容）
- 文字サイズがページをまたいで維持されること、印刷時にヘッダーと固定バーが消えること
- 料金カードの開閉（既定は閉、押すと合計が出る、JSなしでは開いたまま、タップ領域44px）
- ご予約の電話カード（アイコンの丸・色・コントラスト、番号が折り返さないこと、
  カード全体が発信リンクになっていること）
- ドロワーの文字サイズボタン（44px・13px以上・低い画面でもスクロールで必ず押せること）
- ご利用の流れの番号が二重に出ていないこと（マーカーの余白と、描画された文字の両方で）
- お客様の声の飾り引用符が見出しの文字に重ならないこと（要素の枠ではなく行の位置で見る）
- スマホ（iPhone 13）で横スクロールが起きないこと、各ページが3.6〜7.1画面に収まること
